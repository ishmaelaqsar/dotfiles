- Forgejo self-hosted git server

*Hardware:* Raspberry Pi Zero 2W (512MB RAM)\\
*OS:* Raspberry Pi OS Lite (64-bit)\\
*Security:* AppArmor (Enforced) + fail2ban (Active) + Caddy (DNS-01 TLS)\\
*Goal:* Send trusted mail. Push to Git over the LAN at full speed. Keep global access secure.

--------------

** Phase 1: system foundation
*** 1. OS and security preparation
- *OS:* Raspberry Pi OS Lite (64-bit).

- *Enable AppArmor:* append = lsm=apparmor= to the single line in =/boot/firmware/cmdline.txt=. Edit the file by hand. The =sed= command in the next block is not idempotent. A kernel package upgrade can also rewrite the file. Check the flag again after each upgrade.

  #+begin_src sh
  sudo sed -i '$ s/$/ lsm=apparmor/' /boot/firmware/cmdline.txt   # once only
  sudo reboot
  #+end_src

  Check the result after the reboot. If =aa-status= reports =apparmor filesystem is not mounted=, the flag did not take effect. Every AppArmor profile in these notes is then inert:
  #+begin_src sh
  grep -o 'lsm=[a-z,]*' /proc/cmdline
  sudo aa-status
  #+end_src

- *Install the core utilities and the security tools:*

  #+begin_src sh
  sudo apt update && sudo apt upgrade -y
  sudo apt install apparmor apparmor-utils msmtp msmtp-mta fail2ban ca-certificates curl wget rclone -y
  #+end_src

*** 2. SD card longevity (Log2Ram)
#+begin_src sh
curl -L https://github.com/azlux/log2ram/archive/master.tar.gz | tar zx
cd log2ram-master && sudo ./install.sh
sudo reboot
#+end_src

** Phase 2: multi-identity mail relay (msmtp)
This relay sends trusted mail from your domain aliases. It sends the mail through the Google SMTP server.

*** 1. Create the service user first
Create the =git= user and group now so =/etc/msmtprc= can grant read access to both =root= (cron backups) and =git= (Forgejo notifications):

#+begin_src sh
sudo adduser --system --shell /bin/bash --group --disabled-password --home /home/git git
#+end_src

*** 2. Configure the relay: =sudo vi /etc/msmtprc=
Use =syslog LOG_MAIL= instead of a shared log file. A file in =/var/log/msmtp.log= triggers AppArmor =owner= lock errors when both =root= and =git= send mail.

#+begin_src text
defaults
auth           on
tls            on
tls_trust_file /etc/ssl/certs/ca-certificates.crt
syslog         LOG_MAIL
aliases        /etc/aliases

# Personal Identity
account        personal
host           smtp.gmail.com
port           587
from           <user>@<your-domain>.dev
user           <your-gmail-username>@gmail.com
password       <16-character-app-password>

# Forgejo/Dev Identity
account        dev
host           smtp.gmail.com
port           587
from           <dev-alias>@<your-domain>.dev
user           <your-gmail-username>@gmail.com
password       <16-character-app-password>

account default : personal
#+end_src

Lock down permissions to =root:git= (mode 640) and map local system accounts like =root= to a valid RFC 5321 address so Gmail does not reject system mail with =553-5.1.3=:

#+begin_src sh
sudo chown root:git /etc/msmtprc
sudo chmod 640 /etc/msmtprc

sudo tee /etc/aliases >/dev/null <<'EOF'
root: <user>@<your-domain>.dev
default: <user>@<your-domain>.dev
EOF
#+end_src

Edit =/etc/aliases= with your actual address, then test delivery before moving on:
#+begin_src sh
printf "Subject: msmtp test\n\nRelay is working.\n" | sudo sendmail root
#+end_src

** Phase 3: Forgejo git server
*** 1. Installation and directory setup
#+begin_src sh
sudo mkdir -p /var/lib/forgejo/{custom,data,log} /etc/forgejo
sudo chown -R git:git /var/lib/forgejo/
sudo chown root:git /etc/forgejo && sudo chmod 770 /etc/forgejo

VER=15.0.11
BASE="https://codeberg.org/forgejo/forgejo/releases/download/v${VER}"
wget "$BASE/forgejo-${VER}-linux-arm64" "$BASE/forgejo-${VER}-linux-arm64.sha256"

# Verify before you install. This binary runs as a service.
sha256sum -c "forgejo-${VER}-linux-arm64.sha256" || { echo "CHECKSUM FAILED"; exit 1; }

sudo mv "forgejo-${VER}-linux-arm64" /usr/local/bin/forgejo
sudo chown root:root /usr/local/bin/forgejo
sudo chmod 755 /usr/local/bin/forgejo
rm "forgejo-${VER}-linux-arm64.sha256"
#+end_src

*** 2. Config: =sudo vi /etc/forgejo/app.ini=
Replace =<dev-alias>@<your-domain>.dev= with your actual alias (keep single angle brackets around the email address, e.g. =<dev@example.dev>=):

#+begin_src ini
[server]
DOMAIN = git.<your-domain>.dev
ROOT_URL = https://git.<your-domain>.dev/
TRUSTED_PROXIES = 127.0.0.1

[mailer]
ENABLED = true
PROTOCOL = sendmail
SENDMAIL_PATH = /usr/bin/msmtp -a dev
FROM = "Forgejo Hub" <<dev-alias>@<your-domain>.dev>
#+end_src

=TRUSTED_PROXIES= gives Forgejo the true client IP from Caddy. Do *not* add =REVERSE_PROXY_AUTHENTICATION_USER= here. That key names the header which holds an authenticated *username*. Its default is =X-WEBAUTH-USER=. It does not name the client IP. If you set it to =X-Forwarded-For=, the client controls a login name. This becomes a risk when you set =[service] ENABLE_REVERSE_PROXY_AUTHENTICATION= to true.

*** 3. Service: =sudo vi /etc/systemd/system/forgejo.service=
#+begin_src ini
[Unit]
Description=Forgejo Git Server
After=network.target

[Service]
Type=simple
User=git
Group=git
WorkingDirectory=/var/lib/forgejo/
ExecStart=/usr/local/bin/forgejo web -c /etc/forgejo/app.ini
Restart=always
Environment=USER=git HOME=/home/git GITEA_WORK_DIR=/var/lib/forgejo

[Install]
WantedBy=multi-user.target
#+end_src

=sudo systemctl enable --now forgejo=

** Phase 4: local HTTPS gateway (Caddy)
*** 1. Install a custom Caddy (DNS-01)
#+begin_src sh
curl -JL "https://caddyserver.com/api/download?os=linux&arch=arm64&p=github.com/caddy-dns/cloudflare" -o caddy
chmod +x caddy
sudo mv caddy /usr/local/bin/caddy
sudo setcap CAP_NET_BIND_SERVICE=+eip /usr/local/bin/caddy

# The API builds this binary on demand, so there is no published checksum to
# check against. Confirm what you installed instead:
caddy version
caddy list-modules | grep cloudflare
#+end_src

*** 2. Caddyfile: =vi ~/Caddyfile=
#+begin_src caddy
{
    email <your-email>
}

git.<your-domain>.dev {
    tls {
        dns cloudflare {env.CF_API_TOKEN}
        resolvers 1.1.1.1
    }
    reverse_proxy localhost:3000 {
        header_up X-Forwarded-For {remote_host}
    }
}
#+end_src

*** 3. Caddy service: =sudo vi /etc/systemd/system/caddy.service=
#+begin_src ini
[Unit]
Description=Caddy SSL Gateway
After=network.target network-online.target

[Service]
User=<your-username>
Group=<your-username>
EnvironmentFile=/home/<your-username>/.caddy_env
ExecStart=/usr/local/bin/caddy run --environ --config /home/<your-username>/Caddyfile
ExecReload=/usr/local/bin/caddy reload --config /home/<your-username>/Caddyfile --force
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
Restart=on-failure

[Install]
WantedBy=multi-user.target
#+end_src

=sudo systemctl daemon-reload && sudo systemctl enable --now caddy=

** Phase 7: backups, automation, and manual upgrades
*Run the whole job as root.* =/var/lib/forgejo= is =git:git= and mode 750. A normal user cannot read it, and rclone then stops with =permission denied=. Root also reads =/etc/msmtprc=. Root removes both problems, and it needs no sudo rules.

*** 1. Give root its own rclone remote
rclone reads the configuration of the user that runs it. Root has none by default, so copy yours:

#+begin_src sh
sudo mkdir -p /root/.config/rclone
sudo cp ~/.config/rclone/rclone.conf /root/.config/rclone/
sudo chmod 600 /root/.config/rclone/rclone.conf
sudo rclone lsd gdrive:        # must list your folders
#+end_src

*** 2. Add a dead man's switch
Mail tells you when a job *fails*. It cannot tell you when a job never runs at all. A dead-man's switch inverts the logic: silence becomes the alarm.

Create a check at healthchecks.io. Set the period to 1 day and the grace time to 1 hour. Keep the URL out of the script, because the script goes in a public repository. Keep values quoted (or set =HC_URL=""= if unused) so angle brackets in placeholders never trigger a Bash redirection syntax error when the file is sourced:

#+begin_src sh
sudo tee /etc/backup-forgejo.env >/dev/null <<'EOF'
HC_URL=""
# Example when configured: HC_URL="https://hc-ping.com/<your-uuid>"
NOTIFY_EMAIL="<user>@<your-domain>.dev"
EOF
sudo chmod 600 /etc/backup-forgejo.env
#+end_src

Edit =/etc/backup-forgejo.env= to set your real =NOTIFY_EMAIL= address. A self-hosted healthchecks instance works the same way. But put the watchdog on a different host. A watchdog on the host that it watches is worth much less.

*** 3. Backup script: =sudo vi /usr/local/bin/backup-forgejo.sh=
#+begin_src sh
#!/bin/bash
set -euo pipefail

# shellcheck source=/dev/null
[ -r /etc/backup-forgejo.env ] && . /etc/backup-forgejo.env
HC_URL="${HC_URL:-}"
NOTIFY_EMAIL="${NOTIFY_EMAIL:-root}"

ARCHIVE="gdrive:Forgejo_Archive/$(date +%F)"

ping_hc() {   # $1 = "" | /start | /fail
    [ -n "$HC_URL" ] || return 0
    # "|| true": a network fault must never fail the backup itself.
    curl -fsS -m 10 --retry 3 -o /dev/null "${HC_URL}$1" || true
}

notify() {
    printf 'Subject: %s\n\n%s\n' "$1" "$2" | msmtp -a dev "$NOTIFY_EMAIL"
}

# Always bring Forgejo back, even if rclone hangs or the script is killed.
# Without this trap, one bad run leaves the server down until you notice.
trap 'systemctl start forgejo' EXIT

ping_hc /start
systemctl stop forgejo

# --backup-dir keeps the superseded versions. Without it, rclone mirrors a
# deletion, and one bad night destroys the last good copy on the remote.
# Exclude the volatile state. Forgejo rebuilds all of it at startup, and it
# changes at each restart. If you include it, the host and the remote never
# agree. A clean shutdown also moves the SQLite WAL into forgejo.db, so the
# -wal and -shm files are not necessary.
# No --progress: cron has no tty, so it only fills the mail with noise.
rc=0
rclone sync /var/lib/forgejo/ gdrive:Forgejo_Backup \
    --backup-dir "$ARCHIVE" \
    --exclude '/data/queues/**' \
    --exclude '/data/indexers/**' \
    --exclude '/data/sessions/**' \
    --exclude '*.db-shm' --exclude '*.db-wal' || rc=$?

# Start Forgejo before the slow prune. The trap covers an early exit.
systemctl start forgejo

# Keep 90 days of superseded versions, then reclaim the space.
rclone delete --min-age 90d gdrive:Forgejo_Archive || true
rclone rmdirs --leave-root gdrive:Forgejo_Archive || true

if [ "$rc" -eq 0 ]; then
    notify "Backup Success" "rclone sync completed."
    ping_hc
else
    notify "BACKUP FAILED" "rclone sync failed on $(hostname) with code $rc."
    ping_hc /fail
fi
#+end_src

#+begin_src sh
sudo chown root:root /usr/local/bin/backup-forgejo.sh
sudo chmod 700 /usr/local/bin/backup-forgejo.sh
sudo /usr/local/bin/backup-forgejo.sh      # test it before you schedule it
#+end_src

=Forgejo_Archive= must be a *sibling* of =Forgejo_Backup=. rclone refuses a backup directory inside the destination.

*** 4. Automation (=sudo crontab -e=)
Use *root's* crontab, not your own (a normal user crontab cannot run =/sbin/reboot= or read =/etc/msmtprc=). Set =SHELL=, =PATH=, and =MAILTO=""= so =cron= does not attempt to pipe noisy =apt-get= output into =sendmail=:

#+begin_src sh
sudo tee /var/spool/cron/crontabs/root >/dev/null <<'EOF'
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
MAILTO=""

# Daily Backup at 3 AM
0 3 * * * /usr/local/bin/backup-forgejo.sh

# Weekly Update & Reboot. apt-get needs the noninteractive settings, or an
# unattended upgrade blocks on a config-file prompt and never reboots.
0 4 * * 0 DEBIAN_FRONTEND=noninteractive apt-get update -y && DEBIAN_FRONTEND=noninteractive apt-get -y -o Dpkg::Options::=--force-confold upgrade && /sbin/reboot
EOF
sudo chown root:crontab /var/spool/cron/crontabs/root
sudo chmod 600 /var/spool/cron/crontabs/root
sudo systemctl restart cron
#+end_src

Raspberry Pi OS already grants the first user =NOPASSWD: ALL= in =/etc/sudoers.d/010_<your-username>-nopasswd=. Confirm with =sudo cat /etc/sudoers.d/010_*=. Do not add a second sudoers file; root cron needs none.

*** 5. Verify the backup
Always check the backup. An unchecked backup is only an assumption. =rclone check= compares the two sides. It reports the differences, and it changes nothing:

#+begin_src sh
sudo rclone check /var/lib/forgejo/ gdrive:Forgejo_Backup --one-way \
    --exclude '/data/queues/**' \
    --exclude '/data/indexers/**' \
    --exclude '/data/sessions/**' \
    --exclude '*.db-shm' --exclude '*.db-wal'
#+end_src

Use the same exclusions as the sync. The previous run restarts Forgejo at its end, and that restart rewrites the queue, the index and the SQLite scratch files. Without the exclusions, the check always reports these differences.

*** 6. Manual binary upgrade script (Caddy & Forgejo)
Because =caddy= and =forgejo= live in =/usr/local/bin/=, =apt-get upgrade= does not touch them. Install =/usr/local/bin/upgrade-stack.sh= to upgrade Caddy in place (preserving the Cloudflare DNS plugin and =CAP_NET_BIND_SERVICE= capability) and optionally upgrade Forgejo after taking a fresh backup:

#+begin_src sh
sudo tee /usr/local/bin/upgrade-stack.sh >/dev/null <<'EOF'
#!/bin/bash
set -euo pipefail

FORGEJO_VER="${1:-}"

echo "==> Upgrading Caddy..."
/usr/local/bin/caddy upgrade
rm -f /usr/local/bin/caddy.tmp
setcap CAP_NET_BIND_SERVICE=+eip /usr/local/bin/caddy
systemctl restart caddy
echo "==> Caddy active: $(/usr/local/bin/caddy version)"

if [ -n "$FORGEJO_VER" ]; then
    echo "==> Running pre-upgrade backup before installing Forgejo v${FORGEJO_VER}..."
    /usr/local/bin/backup-forgejo.sh

    TMP_DIR="$(mktemp -d)"
    trap 'rm -rf "$TMP_DIR"' EXIT
    cd "$TMP_DIR"

    BASE="https://codeberg.org/forgejo/forgejo/releases/download/v${FORGEJO_VER}"
    BIN="forgejo-${FORGEJO_VER}-linux-arm64"

    wget -q --show-progress "$BASE/$BIN" "$BASE/${BIN}.sha256"
    sha256sum -c "${BIN}.sha256"

    systemctl stop forgejo
    mv "$BIN" /usr/local/bin/forgejo
    chown root:root /usr/local/bin/forgejo
    chmod 755 /usr/local/bin/forgejo
    systemctl start forgejo

    echo "==> Forgejo active: $(/usr/local/bin/forgejo --version)"
else
    echo "==> No Forgejo version passed. (Usage: sudo $(basename "$0") [forgejo-version])"
fi
EOF
sudo chown root:root /usr/local/bin/upgrade-stack.sh
sudo chmod 700 /usr/local/bin/upgrade-stack.sh
#+end_src

Run =sudo /usr/local/bin/upgrade-stack.sh= to upgrade Caddy alone, or pass a version number (such as =sudo /usr/local/bin/upgrade-stack.sh 15.0.12=) to upgrade both Caddy and Forgejo.

** Phase 8: mobile and networking
- *Split-Brain DNS:* In your router, map =git.<your-domain>.dev= to the internal IP of the Pi. This keeps local access fast.

- *SPF Record:* TXT record =v=spf1 include:_spf.mx.cloudflare.net include:_spf.google.com ~all=.

- *Mobile Mail:* Add the identities to the Gmail app with "Send Mail As" in the desktop settings. Use =smtp.gmail.com= and the App Password.

** Phase 9: disaster recovery
*** 1. Re-initialise
Follow *Phases 1-5* on a new SD card. *Do not run the web installer.*

*** 2. Restore the data
#+begin_src sh
sudo systemctl stop forgejo
sudo rclone copy gdrive:Forgejo_Backup /var/lib/forgejo/ --progress
#+end_src

=Forgejo_Backup= holds the current mirror. To recover a file that a later run overwrote or deleted, look in the dated folders under =Forgejo_Archive=:

#+begin_src sh
sudo rclone lsd gdrive:Forgejo_Archive                       # list the dates
sudo rclone copy gdrive:Forgejo_Archive/<date>/<path> ./     # take one file back
#+end_src

*** 3. Permissions and restart
#+begin_src sh
sudo chown -R git:git /var/lib/forgejo/
sudo chmod -R 750 /var/lib/forgejo/
sudo systemctl start forgejo
#+end_src

** Phase 10: troubleshooting
*Tunnel Connectivity:* If the tunnel fails after a reboot, read the log with =sudo journalctl -u cloudflared=. The usual cause is an incorrect system time or an outdated =cloudflared= package. Confirm the APT repo is active with =apt-cache policy cloudflared=.

*SMTP Failures:* Because =msmtp= logs to =syslog=, read mail logs with =sudo journalctl -t msmtp -n 50=. The usual fix is a new Google App Password. The message =account dev not found: no configuration file available= does not mean a missing account. It means the caller cannot read =/etc/msmtprc= (must be =root:git= mode =640=). AppArmor can also block a =passwordeval= command when it enforces the =msmtp= profile. Check with =sudo journalctl -k | grep -i apparmor=.

*Backup Failures:* The job is silent by design, so prove it runs.

#+begin_src sh
sudo crontab -l                                  # the schedule lives in root's crontab
sudo journalctl -u cron --since "7 days ago" | grep backup-forgejo
sudo journalctl -u forgejo --since "7 days ago" | grep -i stopping
sudo bash -x /usr/local/bin/backup-forgejo.sh    # watch a run end to end
#+end_src

=failed to open directory "": open /var/lib/forgejo: permission denied= means the job is not running as root. =didn't find section in config file= means root has no =/root/.config/rclone/rclone.conf= --- see Phase 7 step 1.

Do not trust the folder date in the Google Drive web interface. Drive does not change that date when the contents change. Use =rclone check= instead.
